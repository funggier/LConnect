## Release-qualification defects found and repaired

### Network enumeration truncation

Release qualification reproduced a false-negative `tcp_connections` result on the real host.

Evidence:
- raw `netstat -ano -p tcp`: ~257,870 characters / 3,343 lines
- generic shell output cap: 120,000 characters
- the fixture listener could be truncated before parsing

Repair:
- network endpoint enumeration keeps a dedicated bounded 1,000,000-character capture ceiling
- returned MCP endpoint lists remain independently bounded by their public `limit`
- targeted network smoke passes after repair

### Live browser UIA Unicode result corruption

Physical disposable-Chrome qualification showed Thai/Unicode text was actually accepted by the page, but PowerShell 5.1 worker stdout serialized UIA text as `?`/replacement characters.

Isolation evidence:
- UTF-8 base64 payload decode preserved exact codepoints
- UIA `ValuePattern.SetValue` preserved exact codepoints inside the worker
- native Windows title observation showed the actual page value correctly
- corruption was limited to UIA worker stdout/result serialization

Repair:
- browser-live PowerShell worker explicitly sets `[Console]::OutputEncoding` and `$OutputEncoding` to UTF-8
- post-fix physical source qualification returns Thai/Unicode correctly in type result, UIA snapshot and page title
